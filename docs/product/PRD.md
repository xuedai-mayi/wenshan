# 问山 · 产品定义（PRD）

> 版本 1.0.0 ｜ 状态：已发布 ｜ 最后更新：2026-11-26

## 1. 一句话

**问山把一次地理野外实习的全部资料，变成一个可审核、可追溯、能现场答疑的知识助手。**

带队教师把讲义、PDF、照片、录音、GIS 数据丢进去，系统自动抽出知识草稿；教师确认发布后，学生和教师都能用自然语言问答、看知识图谱、看照片落在真实地形上的位置——答不上来的问题会变成下一轮补资料的清单。

## 2. 问题

地理野外实习的知识生产有一个结构性矛盾：

| 现状 | 后果 |
| --- | --- |
| 资料散落在微信群、网盘、个人 Obsidian、纸质讲义、相机 SD 卡 | 行前备课靠翻旧文件，实习结束后资料沉底，下一届从零开始 |
| 讲解靠教师记忆与临场发挥 | 同一个点位不同教师讲法不同，学生记录质量参差 |
| 学生现场提问超出现场准备 | 教师被问住时无法即时补充，问题当场流失 |
| 通用 RAG / 通用 agent 不理解「点位—路线—日期—地貌」 | 问「锦绣谷附近讲了什么」只能得到关键词匹配，给不出空间与知识链上的答案 |
| 直接把资料丢给大模型 | 无审核、无来源、无法追溯，错的内容会被当成教学结论 |

## 3. 解法

问山不是「又一个 RAG 聊天框」，而是把野外实习的知识生产流程产品化：

```text
资料收录 → 自动抽取草稿 → 人工审核 → 口令发布 → 现场问答 → 缺口登记 → 补资料 → 销缺口
             ↑______________________ 自成长闭环 ______________________|
```

三条设计原则：

1. **AI 起草，人做决定。** 抽取是生成式的，同一份资料两次跑出来的节点数会不同（实测 13 / 18）。所以草稿必须人工核对，发布必须输入完整口令 `确认发布 draft-xxxxxxxx`，普通「可以」「继续」不会触发。
2. **只读与写入物理隔离。** 野外助教模式不注册任何写入工具，只能检索和登记缺口；知识演化模式才能收录、建草稿、发布。
3. **空间是检索的一等公民。** 词法 + 知识图谱双链 + 空间距离三路融合，问「X 附近讲了什么」能按 400 m 内的讲解点作答。

## 4. 平台范围

**1.0 只做桌面 Web 端。** 验收基线：Chrome / Edge / Safari 桌面版，窗口 ≥ 1280×800。

- 服务端是本地 Node 服务，浏览器只是客户端；知识库、模型调用、文件都在服务端。
- 现场使用的主力设备是笔记本与平板横屏，教室场景还要投屏，所以布局按桌面宽屏设计。
- 不做移动端适配与验收、不做原生 App、不做小程序；窄窗口能打开、能问答，但不作为交付标准。
- 移动端原生能力（离线缓存、GPS 联动、语音提问）放在 1.2，做之前不承诺。

## 5. 目标用户

| 角色 | 画像 | 核心诉求 | 使用频率 |
| --- | --- | --- | --- |
| **带队教师**（主要购买者） | 地理/地质/环境院系，带 1—2 周野外实习，15—60 人 | 行前快速备课、现场答疑、实习成果沉淀、下一届可复用 | 行前 1 周集中 + 现场每日 |
| **学生**（主要使用者） | 本科 2—3 年级 | 现场随时问、看点位讲解、回看当天路线照片 | 现场每日 3—10 次 |
| **教研室 / 课程组**（采购决策方） | 3—10 位教师共用一条实习线 | 统一知识口径、教师之间复用、教学评估留痕 | 每学期 |
| **实习基地 / 科普场馆**（扩展场景） | 庐山、黄山、丹霞山等基地 | 把基地知识做成可交互导览 | 长期 |

## 6. 核心场景

**S1 行前备课（教师）**：把历年讲义、论文 PDF、野外记录、照片放进资料夹，系统在后台自动抽取草稿；教师逐条审核、改错、合并，确认发布。产出一套带来源的知识库。

**S2 现场导览（教师/学生）**：用笔记本或平板浏览器打开本机/现场内网服务，问「三叠泉的阶梯状跌水是怎么形成的」，得到带来源的讲解；打开照片地图看当天路线与点位照片。

**S3 即时答疑（学生）**：问到知识库没覆盖的问题，助手明确说「已发布资料中未覆盖」，并把原话登记为知识缺口（重复提问只累计次数）。

**S4 复盘与沉淀（教师）**：实习结束后按缺口清单补资料、重新构建、逐条销缺口；下一届开课时知识库已比上一届更厚。

**S5 多站点复用（教研室）**：换一份 `config/<site>.json`，同一套代码服务另一条实习线。

## 9. 成功指标

**北极星指标：一周内被现场问答命中并引用的已发布知识条数。**

| 层级 | 指标 | 1.0 目标 | 采集方式 |
| --- | --- | --- | --- |
| 激活 | 首次安装到发布第一条知识 ≤ 30 分钟 | ≥ 70% 教师 | 发布事件时间差 |
| 使用 | 实习期内人均每日提问数 | ≥ 5 | 会话事件 |
| 质量 | 检索 Hit@1（152 题） | ≥ 90% | `npm run eval` |
| 闭环 | 缺口从登记到销账的中位时长 | ≤ 7 天 | 缺口事件 |
| 沉淀 | 每届新增已发布节点 | ≥ 50 | 发布事件 |
| 信任 | 发布前被人工修改的草稿比例 | 30%—70%（过低=没审，过高=抽取太差） | 草稿 diff |

## 10. 交付形态

| 形态 | 内容 | 面向 |
| --- | --- | --- |
| 开源自部署 | MIT 源码，自行安装 | 个人教师、技术型团队 |
| 私有化交付 | 源码 + 一条实习线的数据构建 + 部署到院系服务器 + 培训 | 教研室 / 院系 |
| 基地版 | 多站点配置 + 导览页定制 + 运维托管 | 实习基地 / 科普场馆 |
| 培训与共创 | 工作坊：把本院资料做成知识库 | 教师发展中心 |

具体报价与合同条款不在公开文档里，按项目单独沟通。

不做的形态：公有云多租户 SaaS（与「资料不出院系」的核心卖点冲突）。

## 12. 风险与边界

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 生成式抽取不稳定 | 同一资料两次结果不同 | 强制人工审核；草稿 diff；`--force` 重跑 |
| 模型幻觉 | 错误结论进课堂 | 回答必须带来源；未覆盖时明确说「未覆盖」并登记缺口 |
| 模型成本 | 大资料抽取费用不可控 | 分块上限 60、并发 2、`maxTokens` 可配；先小批试跑 |
| 资料授权与隐私 | 照片含人像、论文有版权 | 公开仓库前自查；`data/knowledge/` 与照片默认不进 git；部署在内网 |
| 公网暴露 | 无鉴权的本机服务被扫 | 默认只听 127.0.0.1；公网必须走 Caddy（TLS + basic_auth）并保持 `--trusted-host` 最小化 |
| 凭据泄漏 | 备份包含 API Key | 备份默认 700 目录、`--data-only` 排除凭据、文档明确警告 |
| 地理数据版权 | DEM / 矢量图层再分发受限 | 地形底图本地生成、不随仓库分发第三方素材；公开前确认授权 |

## 13. 术语

- **讲解点**：一次现场讲解发生的点位（含坐标、时间、主题）。
- **知识缺口**：野外助教确认未覆盖的问题，带被问次数与状态（open/resolved）。
- **草稿**：模型抽取出的待审核节点集合，未发布前不进入检索。
- **发布口令**：`确认发布 draft-xxxxxxxx`，存储层强制的发布门禁。
- **三路检索**：词法 BM25（中文二元组）+ 图谱双链扩展 + 空间距离衰减。
