# 问山 · 界面文案规范（UX Copy）

> 依据 ux-writer 2.3 的流程整理。改动界面文字前先看这一页；不在词表里的新叫法，先加进来再用。

## 文案策略卡

**一句话定位**：给地理野外实习的带队教师（主要）和本科生（次要），在行前备课、现场导览和实习复盘时，把一个实习区的资料变成可查询、可导览知识库的桌面 Web 工具。

**用户三问**

- 已经懂：讲解点、路线、PDF、GIS、上传与文件格式。需要解释的是两个自创词：**知识缺口**、**资料夹**。
- 使用情境：备课在桌前细看；现场在讲解间隙快速查。现场场景下，一屏只留能立刻读完的字。
- 来几次：教师跨届长期复用；学生一次实习内多次使用。引导只在第一次出现，之后让路。

**语气表**

| 原则 | 用词 | 详略 | 标点与格式 |
| --- | --- | --- | --- |
| 现场也能一眼读完 | 教师平时会说的词 | 一行一件事，按钮 2—6 字 | 不用「点击」「下方」「右侧」指路 |
| 像同行的助教 | 用「你」；不自夸、不抒情 | 只说下一步和后果 | 不用感叹号；中英文之间加空格 |
| 出错时给下一步 | 说哪不对 + 你能做的那一步 | 一行说完，不编原因 | 不写「请稍后重试」这类空话 |

**对象与动作**

| 对象 | 动作 | 状态 |
| --- | --- | --- |
| 资料、资料夹 | 收录、查看 | 待审核 / 已发布 |
| 草稿 | 审核、发布、驳回 | 待审核 |
| 知识缺口 | 补资料、销掉 | 待补 / 已补 |
| 讲解点、地点、概念、物种、气象、每日、主线 | 查看、定位 | — |
| 照片 | 看、回放路线 | — |

固定叫法：**资料夹**（不叫「文件夹」「总文件夹」混用；仅系统文件选择器文案用「文件夹」）、**知识缺口**、**讲解点**、**知识图谱**、**照片地图**、**知识星系**。

## 每屏一件事

| 屏幕 | 用户来做什么 | 常驻信息 | 按需/删除 |
| --- | --- | --- | --- |
| 知识图谱 | 找到一条知识或一处关联 | 搜索、类型筛选、节点数、操作提示 | 品牌副标题、功能说明、初始「已就绪」提示（已删） |
| 照片地图 | 看某个讲解点/某天的照片 | 日期筛选、播放、图例、缩略图状态 | 缩略图生成命令（已删，交给部署文档） |
| 知识星系 | 从整体看知识结构 | 类型图例、节点/关联数、旋转与缩放 | 「五天实习长成的知识」这类氛围句（已删） |
| 收录资料弹窗 | 把一批资料交进来 | 选文件夹、已选摘要、进度、结果 | 实现解释（已压缩成一句） |
| 缺口面板 | 看还缺什么、怎么补 | 问题、被问次数、处理入口 | 长段说明（已压缩） |

## 写作约定

- 按钮只写动作：`收录资料`、`选择文件夹`、`取消`、`重试`。状态写在按钮旁边，不写在按钮上。
- 错误只说两件事：哪里不对、你能做什么。不写「请稍后重试」「请检查网络」，不把 HTTP 状态码、文件路径、命令丢给用户（细节进 console 与文档）。
- 空态只在用户不知道下一步时出现；控件已在屏上就不写。
- 不用符号代替文字（`×3` 改成 `3 次`，`✓` 改成文字）；emoji 不当图标。
- 自创概念首次出现处解释：知识缺口 = 野外助教没答上来的问题；资料夹 = 本次收录的资料集合。
- 数字用真实值：节点数、关联数、天数都从接口取，不写死「五天」。
